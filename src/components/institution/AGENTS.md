# Institution components
- Student medical records use student-record-files and student_record_documents, accessible only to institution direccion/subdireccion; global admin never bypasses this rule, signed links expire in 30 seconds.
- Delegated membership changes use lead_set_institution_member: institution direccion or global admin may assign all institution roles, never self or global admins, with serialized audited writes; membership never grants global roles or payment entitlement.
- Institutional notes/orders are immutable issued rows with server-derived signer/hash; public verification exposes only center/type/date, and browser PDF generation never substitutes for the stored approval.
- Institution permissions: reviewers are Max or that institution's direccion via can_review_permissions, never self; approval stores a canonical payload plus SHA-256 and public verification recomputes it, exposing only masked holder data.
- Permission support is an append-only request/response workflow with owner file paths and existing reviewer checks; requesting evidence never changes approval status or grants access.
- Institution channels: access comes only from channel_access (students read their section, never post or join family channels); the database filters language, family attachments wait for direccion/guide review, and photos are re-encoded client-side to drop location metadata.
- Student follow-up reads only through student_follow_up/can_follow_student (consented family, direccion, administrativo/orientación, section guide, Max); SQL helpers must coalesce NULL role checks to false.
- Schedule generator: pure seeded greedy in src/lib/schedule.ts, saved to institution_schedules (direccion/subdireccion/administrativo/admin write, staff read); students and families never see the tab.
- Schedule cell edits prepare local changes, validate same-period teacher/room conflicts, and explicitly update the selected institution-scoped saved row under existing RLS; never silently write generated previews.
- Institution logos: direccion of that institution or Max change them via set_institution_logo with a validated {inst}/logo-*.ext path; other roles never.
- Institution documents: institution_documents + private institution-docs bucket under {inst}/; members read, only direccion or Max upload/delete.
- Institution documents, permission proofs, enrollment and channel files open by authenticated download under current storage RLS (open-private-file.ts or server bytes), never transferable signed URLs; downloaded copies cannot be remotely revoked.
- Student visibility is institution-scoped, director/admin-audited, enforced on practice load and scoring; section schedules project assigned allowed grids only, with consented guardian checks.
- Institutional area reviews require director/admin decisions and reasons with private append-only history; student practice loading/scoring requires both an approved subject and an individual assignment.
- Family result breakdowns use student_follow_up for platform attempts and RLS-scoped institution_practice_results for server-scored institutional submissions; never infer scores from counters or add institutional results to academic XP, streaks or certificates.
- Practice answer previews read existing staff-scoped drafts; publication requires reviewing the exact row and privacy confirmation, with canonical keys never sent to students or families.
- Editorial campaigns adapt Campana Clara planning/export, not its auth or local approval store; institution_resources keeps role-scoped drafts and director/admin publication. PDF copies stay in a separate private bucket with no-store public delivery conditioned on publication, so withdrawal hides them without exposing student documents.
- Completion analytics aggregate server-scored institutional submissions without user IDs or answers; repeated submissions count again and test institutions are excluded.
- Institutional payment validity is returned only to that institution's direccion (my_institutions) or Max (admin_institutions); institution_paid_until is not client-callable; sandbox checkout remains disabled without verified sandbox configuration, never substituting live checkout.
- Resource read/send grants enforce assignment in database and storage; official adult contacts are manager-only, and sends stay blocked without verified Business delivery processing.
- Specification tables are session-local and computed by pure src/lib/spec-table.ts (largest-remainder apportioning keeps exact totals); no student data stored.
- Subdirection campaign/publication approval uses institution-scoped database policies and guards; UI leadership never grants role assignment, payment visibility or unrelated personnel powers.
- Institution document views share InstitutionDocumentHeader using the selected center's logo; uploaded originals are never silently rewritten.
- Campaña Clara reuses the approved public editorial catalog; institution search selection opens existing authorized panels without granting channel or editorial access.
- Enrollment contacts and attachment manifests are immutable private submissions; authenticated server handlers verify owned stored bytes before privileged insertion, and approval remains in review_enrollment, never in client-selected profile labels.
- Pickup proposals use separate auditable status rows; institution review requires approved enrollment and never permits guardian self-approval, while image consent and document hashes never grant publication or pickup authority.
- Pickup scanners decode QR/barcodes locally; opaque QR IDs and exact identification queries use authenticated caller RLS and no-store live status, never public identity lookup or camera uploads.
- School services use school_service_action for auditable writes and per-institution operator checks; ticket credit requires confirmed purchases and delivery locks prevent duplicate or negative spending, separate from subscriptions and academic records.
- Institution tariffs/discounts are immutable price rows (only deactivation, history kept) managed by school_service_manager; enrollment amounts come only from price_enrollment, which applies the single highest-priority eligible discount and stores an append-only snapshot used by the browser PDF.
- Max's role preview filters institution tabs by a presentation allow-list within his own session; underlying queries and RLS stay unchanged and no other person's identity is simulated.
